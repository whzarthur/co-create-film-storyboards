# 场景调度图：设计草稿 → 资产校准 → 正式坐标图

现已收到作者的实际工具包。默认按 [blocking-toolkit.md](blocking-toolkit.md) 使用保留的 Python 渲染器、JSON 模板和 PNG 参考图；下文关于“未取得工具包”的历史说明仅描述此前资料来源，不再作为当前能力限制。

依据作者提供的《聊天记录_场景调度图工作流_2026-09-15.html》提炼。记录中的示例尺寸、人物坐标、工具路径和已创建文件均属于原会话，不移植为本项目事实，也不宣称已取得其中提到的脚本或工具包。模型解析效果等经验说法不作为保证。

## 按场判断，按镜引用

以下任一命中，场景需建立调度图，资产校准后升级为精确坐标版：

- 需要组织位置关系的同框人物 ≥3。
- 同一场景使用机位 ≥2。
- 同一场景复用 ≥2 次。
- 虽不满足数量阈值，但存在必须交代的 A→B 走位，或空间本身承担叙事，如对峙、包围、追逐。

三档交付：文字站位表 → 调度草稿 → 正式坐标图。不要把数量相乘当成评分公式；按空间复杂性和上述条件判断。人群可按叙事需要分组，不必逐个定位无关群众。

单人口播、一次性单镜头、无人氛围空镜、纯局部特写、无需稳定坐标的抽象空间，通常文字说明足够。例外：特写所属场戏有全景或多机位，则仍要场级图；特写只引用对应锚点或局部区域。空镜若建立后续复用的关键空间，也应参与场级锚点设定。

## 阶段 A：分镜设计时画草稿

1. 从剧本与已确认镜头抽取人物站位/朝向、机位、关键道具/建筑、动线。先读取已有概念草稿或分镜草图；没有图时可按已知关系拟定布局，标注待作者确认，不冒充实测。
2. 使用俯视平面图保留场景结构，优先 SVG 或确定性绘图。不同于主分镜画面的精细铅笔素描要求，调度图以准确清楚为先。
3. 每场建立一个主图，镜头用 C1/C2 等机位和阶段叠加层引用；同场人物变化大时用开始/过程/结束状态或小分图，不能把不同时刻的站位混成一张静态图。
4. 标记场景编号、版本、草稿状态、坐标方向、图例。无真实尺寸时用归一化/示意坐标，并标“非实测、非比例”；原点和方向需统一，“上=舞台/入口”不等于地理北。已确认坐标与拟定坐标分开。
5. 在逐镜讨论中展示有关局部，询问本镜关键站位或动线；确认后同步更新图和记录。无需重新逐项确认作者已接受的布局。

## 阶段 B：数字资产形成后校准

资产图负责外观、材质、光影和道具造型；调度图负责站位、机位、动线；角色参考图负责人物外观。三者各自引用并关联版本，不互相替代。

典型顺序：已确认分镜/草稿 → 场景概念空镜 → 多角度与俯视衍生图 → 物理锚点校验 → 正式坐标图。允许美术先行。衍生图优先共同引用同一已确认概念图或稳定参考组，避免只从上一张不断衍生造成漂移。

- 有可靠俯视图/平面图：沿其结构叠加人物、机位和动线，确认比例与方向。
- 只有透视资产图：识别可见物理锚点并推定平面关系；单张透视图通常无法唯一恢复实际尺度，不制造精确米数。遮挡区域标为未知，必要时补视图或由作者确认设计。
- AI 生成俯视图只能作为候选：可要求正交俯视、垂直向下、无透视、包含全部关键锚点，随后仍要核对；不能直接相信模型给出的坐标。
- 概念图、多角度图和俯视图互相核对门窗、舞台、通道、桌椅、固定道具等稳定锚点的数量、左右/前后、连接关系、相对距离、朝向及通行空间。角色、阴影、可移动道具不宜充当唯一固定锚点。

## 仲裁与更新

“先定稿者为锚”指已确认版本，不是最早出现的草图。新资产到达不等于自动覆盖已确认调度；先区分美术差异、未定区域和实际空间矛盾。

草稿尚未定稿时，按经校验的场景资产更新坐标；已确认的重要站位/走位与资产冲突时，向作者提出修改资产或修改调度的具体方案，不静默改变剧情。最终美术以已确认概念图为准、空间以已校准调度图为准，两者必须相容，不能把矛盾直接交给视频模型。

维护锚点表：锚点 ID、名称、草稿位置、资产依据（文件及视角）、校准位置、确定/推测/未知状态、差异处理。正式图注明依据的资产版本；固定锚点变化后标记旧图待复核。

更新链：场景资产 → 锚点表 → 调度图 → 引用该场景的镜头与参考首帧 → 方位提示词。检查机位是否穿墙、路线是否碰撞、视线是否合理；列出受影响镜号，不改无关镜头。只声称核对过实际可读的图，不声称全空间已被验证。

## 正式交付与下游

适用场景提供平面图、坐标信息表及可编辑源数据（推荐 JSON）。有尺寸依据时标单位米；无依据时保留示意坐标和限制，不因“精确版”名称伪造精度。机位标朝向、运动路径；FOV、焦距、机高仅在已确定且有适用依据时标数值。

HTML 中默认嵌入现成工具输出的 PNG，保留 JSON 供修改；需要交互图层时才额外提供 SVG。确定性渲染保持坐标与图一致。工具的使用与限制参见 blocking-toolkit.md。

### 在分镜卡中引用

场级图与页面显示分开处理：一张场级 PNG/JSON 可以被多个镜头引用，不代表要为每镜重新绘制或复制一份源文件。

- 默认把调度图放进对应分镜卡的机位/连续性区域，以小型 16:9 缩略图显示；缩略图只高亮并显示当前镜头实际使用的机位，其他机位隐藏。只有正反打、越轴或镜间衔接确实需要比较时，才保留一个相关机位并降灰，避免把全场机位信息塞进每张卡片。
- 场景或状态首次出现的分镜卡提供紧凑的“查看全场机位”入口，打开包含全部机位的场级总图；不把总图重复放入后续卡片。标签写明场景或状态、当前机位、适用镜号以及“草稿/待确认/待校准”等状态。
- 缩略图支持鼠标点击和键盘打开灯箱，放大后显示完整原图；Esc、点击遮罩关闭，并把焦点还给原缩略图。
- 同一场景的聚焦图应从同一份场级 JSON 派生，保留人物、道具、轴线和固定锚点，只过滤机位及与本镜无关的临时动线，不另行手工设计空间。人物位置发生阶段性变化时，各镜头引用相应的开始、过程或结束状态；跨越两个状态的转折镜头可以并列显示两个聚焦缩略图。
- 默认不在镜头卡片之外再铺设全宽调度图区，以免打断逐镜阅读并占用过多篇幅。作者明确要求空间总览，或调度图本身是主要交付物时，才增加独立总览。
- 自包含 HTML 中相同的总图或聚焦图只嵌入一次，再由多个分镜卡复用该数据；不要因多镜引用而重复写入大段 base64。多个镜头共用同一机位与状态时可共用一张聚焦图；不同机位才派生不同图，并检查最终文件体积。

提示词阶段消费已确定空间：将坐标翻成相对当前机位可见的自然方位，如“主角居中、同伴在其左后方、门在远景右侧”。平面左右不直接等于画面左右。需要时按调度合成人物首帧；多机位使用同一组场景锚点和角色参考，但各自生成符合对应视角的首帧，不把同一透视空镜硬用于所有角度。实际提交几张参考图取决于工具能力。

## 阶段状态

至少区分：文字即可／调度草稿·待确认／调度设计已确认·待资产校准／资产矛盾待处理／已校准正式图。作者要求边问边做时，即刻输出适用场景草稿，资产不足只影响校准状态，不应一直拖到最终导出才画。
